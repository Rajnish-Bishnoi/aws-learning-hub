1. AMI — Amazon Machine Image

📚 What is AMI?

AMI is a template/image of an EC2 instance. It can contain the operating system, installed software, configuration and other required settings.

We can use an AMI to launch another EC2 instance with the same configuration.

🧪 My Practical

  1. EC2 create kiya.
  2. Docker install kiya.
  3. EC2 ki AMI create ki.
  4. AMI se second EC2 launch kiya.
  5. Second EC2 mein Docker check kiya.
  6. Docker already installed tha because AMI mein configuration included thi.

💡 Easy Example

Suppose EC2-1 mein Docker, configuration aur required software installed hai.

Us EC2 ki AMI bana di.

Ab AMI se EC2-2 launch karenge.

EC2-2 mein same base configuration mil sakti hai.

⚠️ AMI aur Snapshot same cheez nahi hain. AMI EC2 launch karne ke liye image/template hoti hai, while Snapshot EBS volume ka point-in-time backup hota hai.

2. EBS Volume

📚 What is EBS?

EBS stands for Elastic Block Store. It provides block storage that can be attached to an EC2 instance.

🧪 My Practical

  1. Volume-1 create kiya.
  2. Volume-1 ko EC2-1 ke saath attach kiya.
  3. Volume check kiya using lsblk.
  4. File system check kiya.
  5. File system create kiya.
  6. Mount point create kiya.
  7. Volume mount kiya.
  8. Important file create ki.
  9. Permanent mount ke liye /etc/fstab configure kiya.

💻 Important Commands

lsblk

file -s /dev/nvme1n1

mkfs -t ext4 /dev/nvme1n1

mkdir /mnt/data

mount /dev/nvme1n1 /mnt/data

umount /mnt/data
💡 Agar new volume mein data store karna hai, to mounted directory ke andar data store karo. Example: /mnt/data

3. EBS Snapshot

📚 What is Snapshot?

Snapshot is a point-in-time backup of an EBS volume.

🧪 My Practical

  1. Volume-1 create kiya.
  2. Volume-1 ko EC2-1 se attach kiya.
  3. Volume ko mount kiya.
  4. Important file create ki.
  5. Volume-1 ka snapshot create kiya.
  6. Snapshot se Volume-2 create kiya.
  7. Volume-2 ko EC2-2 se attach kiya.
  8. Volume-2 ko mount kiya.
  9. Important file check ki.
💡 Snapshot → New EBS Volume → Attach → Mount → Data check

4. Copy AMI & Snapshot to Another Region

AMI Cross Region

  1. EC2 ki AMI create karo.
  2. AMI select karo.
  3. Copy AMI option choose karo.
  4. Destination region select karo.
  5. AMI copy karo.
  6. New region mein AMI available hogi.
  7. Us AMI se EC2 launch karo.

Snapshot Cross Region

  1. Snapshot create karo.
  2. Snapshot select karo.
  3. Copy Snapshot choose karo.
  4. Destination region select karo.
  5. Snapshot copy karo.
  6. New region mein snapshot se EBS volume create karo.
  7. Volume ko EC2 se attach karo.
  8. Mount karo.
💡 Basic flow: AMI → Copy AMI → New Region → Launch EC2 Snapshot → Copy Snapshot → New Region → Create Volume → Attach → Mount

5. EC2 Instance Type

📚 What is Instance Type?

Instance type defines the compute resources available to an EC2 instance, such as CPU, memory, networking and storage capabilities.

Common Categories

  • General Purpose
  • Compute Optimized
  • Memory Optimized
  • Storage Optimized
  • Accelerated Computing

6. EC2 User Data

📚 What is User Data?

User Data allows us to run commands or scripts during EC2 launch. It is commonly used for initial configuration and software installation.

💻 Example

#!/bin/bash

yum install docker -y
💡 User Data can automate the initial setup of an EC2 instance.

7. VPC

📚 What is VPC?

VPC stands for Virtual Private Cloud. It is a logically isolated network in AWS where we launch resources.

Main Components

8. VPC Peering

📚 Concept

VPC Peering creates a network connection between two VPCs so resources in those VPCs can communicate using private IP addresses, subject to routing and security configuration.

Simple Company Example

Suppose Company has:

  • VPC-1 → Application
  • VPC-2 → Database

VPC Peering can be used to establish private connectivity between the VPCs.

9. Transit Gateway

📚 Concept

AWS Transit Gateway acts as a central network hub that can connect multiple VPCs and other supported networks.

Simple Example

VPC-1
   \
VPC-2 ---- Transit Gateway ---- VPC-3
   /
VPC-4

Instead of creating many individual VPC Peering connections, a central Transit Gateway can simplify the network architecture.
